    How this was built, and how it would scale

    Where the demo data came from

    A Python script, run once on a PC, asked OpenStreetMap (a free, public map database) for every martial arts, BJJ, yoga, CrossFit and Pilates studio in Baltimore. It dropped chains and multi-location brands, then visited each studio's own website and read the home, about, team, board, contact and schedule pages. From those pages it recorded owner and staff names with their titles, any email addresses the studio publishes, and the booking and marketing software in the site's code.

    Could the same script cover the whole country?

    Yes. OpenStreetMap covers the whole US, and the script would only need a bigger search area. But a nationwide database of studio owners isn't what's needed here, and it would go stale quickly.

    The better fit: enrich each lead when the form is submitted

    The same logic can run on one lead at a time, at the moment a HubSpot Contact Us form comes in:

    1. The form submission triggers a HubSpot workflow, which sends the email and studio name to a small cloud function. Adding a required "Studio name" field to the form covers Gmail-style addresses.
    2. The function finds that one studio, by its email domain, a studio name in the email handle, or the name typed on the form, using a free business-listing source such as OpenStreetMap or Foursquare's open places data.
    3. It reads that studio's website, checks whether the person is named there and in what role, and detects its booking software.
    4. It writes the result back to the HubSpot contact and company: matched studio, the person's role, segment, and tech stack.

    Nothing is stored except what's written to that one contact record. Each check takes a few seconds and costs fractions of a cent.
